Le **Construction Tender Assembly Builder** est une application navigateur et un modèle d'estimation Excel conçus pour automatiser la préparation des offres de construction, gérer le BOQ (Bill of Quantities / bordereau des quantités) et standardiser les calculs de coûts.

En transformant les estimations historiques en actifs d'entreprise réutilisables, ce logiciel d'estimation d'appels d'offres de construction réduit le temps de préparation des offres de plusieurs semaines à quelques heures. Disponible en version web gratuite ou en classeur Excel téléchargeable pour les estimateurs professionnels et les métreurs.

## Ce qu'il vous aide à suivre

## Surmonter les défis courants de l'estimation de construction

Ce classeur est conçu pour résoudre les goulets d'étranglement les plus fréquents de la **préparation des offres de construction** et de l'**ingénierie des coûts** :

*   **Prévenir les oublis de périmètre dans le BOQ :** Arrêtez de perdre de la marge à cause d'articles manquants. Le moteur de mapping d'appels d'offres recoupe automatiquement les nouveaux bordereaux quantitatifs (BOQ) avec les bases de données historiques pour garantir l'exhaustivité du périmètre.
*   **Réutiliser les données de construction historiques :** Arrêtez de repartir de zéro à chaque offre. Convertissez les estimations de projets passés en bibliothèques d'assemblages dynamiques et réutilisables (Assembly Builder) accessibles instantanément.
*   **Atténuer les risques de productivité du travail :** Évitez d'utiliser des taux de main-d'œuvre obsolètes. Appliquez des facteurs d'ajustement de productivité dynamiques aux données de travail historiques pour correspondre aux conditions actuelles de chantier et aux taux du marché.
*   **Standardiser les codes de coûts (WBS) :** Éliminez les reprises après l'appel d'offres. Structurez automatiquement vos estimations à l'aide de codes de coûts standardisés, instantanément exportables vers des logiciels de gestion de projet comme Procore.

## Comment utiliser le classeur d'estimation : guide de démarrage rapide

### 1. Configuration des paramètres de coûts de construction
Ouvrez l'espace de travail **Settings** pour définir votre base d'estimation d'entreprise. Établissez des règles standardisées pour vos offres :
*   **Majoration & frais généraux :** Définissez les marges brutes cibles et les pourcentages de frais généraux.
*   **Risque & imprévu :** Fixez les provisions de risque de base pour les matériaux de construction volatils.
*   **Productivité du travail :** Appliquez des facteurs d'ajustement régionaux aux taux de main-d'œuvre du bâtiment.
*   *Résultat :* Définissez ces paramètres une seule fois pour établir votre **framework de modèle d'estimation de coûts** maître.

### 2. Import des données BOQ (bordereau quantitatif)
Intégrez transparentement vos données d'appel d'offres existantes sans migration de base de données complexe. Collez les données brutes directement depuis des outils de métré externes, des systèmes comptables ou des documents de consultants du client dans les feuilles de calcul désignées :
*   Tender BOQ (Bill of Quantities)
*   Subcontractor Schedule of Rates (SOR)
*   Material Quantity Takeoffs (QTO)

### 3. Automatisation du mapping d'assemblages & du calcul des coûts
Passez au **Estimating Engine**. Le classeur exécute automatiquement la logique suivante :
*   Effectue la **normalisation du BOQ**, en associant les nouvelles lignes d'appel d'offres à vos assemblages de construction historiques.
*   Calcule avec précision les coûts de main-d'œuvre, de matériaux et d'équipement selon vos règles de productivité prédéfinies.
*   Génère une **sortie d'estimation de coûts** prête pour l'appel d'offres, avec une ventilation transparente des risques et des marges.
*   👉 [*Tester le mapping d'assemblages automatisé dans le navigateur*](https://hyvoid.github.io/construction-estimating/)

### 4. Construire une base de données d'estimation d'entreprise réutilisable
Après la soumission de l'offre, ne jetez pas le fichier. Vos nouveaux mappings et assemblages WBS (Work Breakdown Structure) personnalisés sont enregistrés directement dans le **History Repository**. Le système évolue à chaque offre, transformant des tableurs à usage unique en une **base de données d'estimation de construction** permanente.
*   👉 [*Télécharger le classeur d'estimation Excel pour un usage hors ligne*](https://theseusworkshop.com/l/prkvr?utm_source=github&utm_medium=GitHub%20README)

## Pourquoi j'ai conçu cet outil : le problème de la « mémoire d'estimation »

Après avoir analysé des centaines d'offres de construction et collaboré avec des équipes commerciales, j'ai pris conscience d'une vérité fondamentale : **La plupart des entreprises de construction ne souffrent pas vraiment d'un manque de logiciels d'estimation. Elles souffrent d'un manque de mémoire d'estimation institutionnelle.**

Dans de nombreuses équipes de métré (QS) et d'estimation, le workflow de préparation des offres ressemble encore à ceci :

```text
New BOQ Received
      ↓
Review Architectural Drawings
      ↓
Search Siloed Spreadsheets & Old Files
      ↓
Copy Previous Project Estimate
      ↓
Manually Modify Cost Rates
      ↓
Submit Tender (with hidden commercial risks)
```

## Trois pièges qui surprennent même les estimateurs expérimentés

### Piège 1 — Réutiliser des estimations historiques sans normalisation du périmètre

Une décision a été prise :

> Utiliser le projet A comme base du projet B.

L'estimation reposait sur une hypothèse passée inaperçue :

> Les catégories de périmètre étaient supposées identiques.

| Historique | Nouvel appel d'offres |
| ---------- | ---------- |
| Excavation | Terrassement |
| Structure | Béton   |
| Services   | CVC        |

Résultat :

* 18 % des coûts ont été omis.

Le raisonnement est incorrect car la terminologie des appels d'offres correspond rarement aux définitions opérationnelles du périmètre.

Approche correcte :

```text
Tender Item
      ↓
Scope Mapping
      ↓
Assembly Matching
      ↓
Cost Library
```

Résultat correct :

* Exhaustivité du périmètre rétablie.
* Variance d'estimation considérablement réduite.

<details>
<summary>Logique des formules</summary>

```excel
=XLOOKUP(Tender_Item,
Mapping_Table[Tender],
Mapping_Table[Assembly])

=SUMIFS(Costs[Amount],
Costs[Assembly],
Current_Assembly)
```

</details>

---

### Piège 2 — Supposer que la productivité historique reste valable

Décision :

> Utiliser les taux de main-d'œuvre et la productivité de l'année dernière.

Hypothèse erronée :

> La productivité reste constante.

Exemple :

| Année     | Productivité |
| -------- | ------------ |
| Précédente | 8 m²/hr      |
| Actuelle  | 5.9 m²/hr    |

Résultat :

* Coûts de main-d'œuvre sous-estimés de 35 %.

Approche correcte :

```text
Historical Productivity
       ×
Adjustment Factor
       ×
Current Conditions
```

Résultat correct :

* Les estimations de main-d'œuvre reflètent les conditions actuelles du marché.

<details>
<summary>Logique des formules</summary>

```excel
=Base_Productivity
* Adjustment_Factor

=Quantity
/ Adjusted_Productivity
```

</details>

---

### Piège 3 — Appliquer la marge avant le risque

Décision :

> Appliquer directement la marge cible.

Hypothèse erronée :

> L'exposition au risque est déjà prise en compte.

Résultat :

```text
Cost = $10M
Margin = 10%
Bid = $11M
```

Risque non reconnu :

```text
Risk Exposure = $1.5M
```

Approche correcte :

```text
Base Cost
      +
Risk
      +
Contingency
      +
Margin
```

Résultat correct :

```text
$10M + $1.5M + 10%
= $12.65M
```

<details>
<summary>Logique des formules</summary>

```excel
=Direct_Cost
+ Risk
+ Contingency

=Adjusted_Cost
* (1+Margin)
```

</details>

## Exemple de scénario

Un entrepreneur reçoit un appel d'offres pour l'agrandissement d'un hôpital.

Entrée :

| Élément                | Valeur |
| ------------------- | ----- |
| Valeur de l'appel d'offres        | $48M  |
| Articles du BOQ           | 1 240 |
| Projets historiques | 42    |
| Assemblages existants | 680   |

Traitement :

```text
1240 BOQ items
        ↓
892 auto-mapped
        ↓
278 assembly matches
        ↓
348 manual reviews
```

Sortie d'estimation :

| Composante      | Coût   |
| -------------- | ------ |
| Matériaux      | $19.4M |
| Main-d'œuvre | $11.2M |
| Équipement      | $5.1M  |
| Sous-traitants | $7.8M  |
| Frais généraux      | $1.6M  |
| Risque           | $1.9M  |

Offre finale :

```text
Direct Cost:
$45.1M

Margin:
8%

Tender Price:
$48.7M
```

Implication opérationnelle :

Au lieu de passer trois semaines à reconstruire des estimations historiques, l'estimateur se concentre uniquement sur les exceptions de périmètre et la stratégie commerciale.

## Règles de validation

| Champ          | Règle                     | Comportement en cas d'erreur     |
| -------------- | ------------------------ | ------------------ |
| Code de coût      | Doit exister dans la bibliothèque    | Avertissement de validation |
| ID d'assemblage    | Doit être unique           | Rejeter la saisie       |
| Quantité       | Supérieure à zéro        | Signaler l'erreur    |
| Productivité   | Dans la plage acceptée    | Avertissement            |
| Marge         | Entre 0–50 %            | Rejet             |
| Escalade     | Entre -20 % et +50 %    | Avertissement            |
| Mapping d'appel d'offres | Doit résoudre en un assemblage | File d'attente des exceptions    |
| Export Procore | WBS valide requis       | Export bloqué     |

</details>
