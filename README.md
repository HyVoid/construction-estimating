#### Architecture Principles

1. **Separate standard costs from project-specific quantities:** The Cost Library stores reusable unit rates; Tender Import stores client-specific BOQ quantities, bridged via the Assembly Library and Tender Mapping layers.
2. **Use assemblies as the estimating interface:** A construction activity is represented by an Assembly ID containing multiple underlying cost components and usage factors.
3. **Keep pricing assumptions centralized:** `01_Settings` acts as the single control point for overhead, risk, and margin parameters.
4. **Preserve component-level cost traceability:** `06_Estimate_Engine` calculates tender sell prices, while `07_Procore_Export` reconstructs underlying component direct costs rather than exporting composite assembly rates.
5. **Separate estimating outputs from source data:** Dashboards and exports consume calculated results without requiring manual restructuring of source records.

### Three Traps That Catch Even Experienced Construction Estimators

#### Trap 1: Treating an Assembly Rate as a Direct Resource Cost

**The decision:** Reuse a historical unit rate for a new tender item.

**The hidden problem:** The historical rate is a composite construction assembly, not an individual resource price. Material quantities, labor requirements, equipment consumption, and subcontract contributions may differ under the new specification.

| Approach | Estimating Result |
|---|---|
| Incorrect | Apply the historical $70.90/$\text{m}^2$ rate without checking its composition. |
| Corrected | Review concrete, reinforcement, formwork, labor, and pumping quantities against the new specification before reusing. |

<details>
<summary>Calculation Reference — Assembly Component Cost</summary>

```excel
Extended Cost = Usage Factor * Component Unit Rate
Assembly Base Rate = SUM(Extended Cost)
```

Component rate lookup from `02_Cost_Library`:

```excel
=XLOOKUP(
    C2:INDEX(C:C,COUNTA(C:C)),
    '02_Cost_Library'!A2:A10000,
    '02_Cost_Library'!H2:H10000,
    0
)
```

</details>

#### Trap 2: Confusing Markup with Profit Margin

**The decision:** Increase direct construction cost by one percentage and assume the resulting amount represents intended profit.

**The hidden problem:** Overhead, risk allowance, and margin are distinct pricing components. Applying margin to the wrong cost base changes the final selling price.

Assume Direct Cost = $70,900, Overhead = 10%, Risk = 5%, Target Margin = 12%:

| Calculation | Amount |
|---|---:|
| Direct cost | $70,900.00 |
| Overhead (10% of direct cost) | $7,090.00 |
| Risk allowance (5% of direct cost) | $3,545.00 |
| Subtotal before margin | $81,535.00 |
| Margin (12% of subtotal) | $9,784.20 |
| **Final selling price** | **$91,319.20** |

<details>
<summary>Calculation Reference — Tender Pricing</summary>

```excel
Overhead Amount = Base Cost Total * Overhead Rate
Risk Allowance = Base Cost Total * Risk Rate
Subtotal Before Margin = Base Cost Total + Overhead Amount + Risk Allowance
Margin Amount = Subtotal Before Margin * Margin Rate
Final Sell Price = Subtotal Before Margin + Margin Amount
```

Expressed mathematically:

$$\text{SellPrice} = \text{DirectCost} \times (1 + \text{OverheadRate} + \text{RiskRate}) \times (1 + \text{MarginRate})$$

*Note: This is a sequential markup model; the margin amount is applied to the pre-margin subtotal rather than expressed directly as gross margin on final revenue.*

</details>

#### Trap 3: Exporting Composite Assembly Costs Instead of Project Cost Components

**The decision:** Transfer the final composite assembly rate directly into the project budget.

**The hidden problem:** A composite rate is useful for tendering, but loses the resource-level separation (concrete, steel, formwork, labor, pumping) needed for job-cost tracking.

For $1,000\text{ m}^2$ of slab work, component-level original budgets should be:

| Cost Component | Original Budget |
|---|---:|
| Concrete | $22,500.00 |
| Reinforcement | $14,400.00 |
| Formwork | $18,000.00 |
| Labor | $12,250.00 |
| Pumping | $3,750.00 |
| **Total** | **$70,900.00** |

```excel
Component Budget = Tender Quantity * Usage Factor * Component Unit Rate
```

<summary>05 — Procore Export: Component-Level Budget Reconstruction (`07_Procore_Export!A2`)</summary>

```excel
=LET(
    tender_mapped,
        FILTER(
            '05_Tender_Mapping'!A2:G10000,
            ('05_Tender_Mapping'!A2:A10000<>"")*
            ('05_Tender_Mapping'!D2:D10000<>"")
        ),
    item_nos, CHOOSECOLS(tender_mapped,1),
    qtys, CHOOSECOLS(tender_mapped,3),
    assembly_ids, CHOOSECOLS(tender_mapped,4),
    REDUCE(
        {"WBS Code","Cost Code","Category","Original Budget"},
        SEQUENCE(ROWS(tender_mapped)),
        LAMBDA(
            acc, idx,
            LET(
                current_wbs, INDEX(item_nos,idx),
                current_qty, INDEX(qtys,idx),
                current_assembly, INDEX(assembly_ids,idx),
                assembly_components,
                    FILTER(
                        '03_Assembly_Library'!C2:G10000,
                        '03_Assembly_Library'!A2:A10000=current_assembly
                    ),
                comp_codes, CHOOSECOLS(assembly_components,1),
                comp_factors, CHOOSECOLS(assembly_components,2),
                comp_rates, CHOOSECOLS(assembly_components,4),
                row_budget,
                    MAP(
                        SEQUENCE(ROWS(assembly_components)),
                        LAMBDA(
                            r_idx,
                            LET(
                                code, INDEX(comp_codes,r_idx),
                                factor, INDEX(comp_factors,r_idx),
                                rate, INDEX(comp_rates,r_idx),
                                sub_budget, current_qty*factor*rate,
                                category,
                                    IFS(
                                        XLOOKUP(code,'02_Cost_Library'!A2:A10000,'02_Cost_Library'!D2:D10000,0)>0,"M",
                                        XLOOKUP(code,'02_Cost_Library'!A2:A10000,'02_Cost_Library'!E2:E10000,0)>0,"L",
                                        XLOOKUP(code,'02_Cost_Library'!A2:A10000,'02_Cost_Library'!F2:F10000,0)>0,"E",
                                        TRUE,"S"
                                    ),
                                HSTACK(current_wbs,code,category,sub_budget)
                            )
                        )
                    ),
                VSTACK(acc,row_budget)
            )
        )
    )
)
```

**Implementation notes:** Classifies each Cost Code by its first positive resource rate (M → L → E → S); uses tender item number as default WBS; exports direct component budgets (excluding commercial overhead, risk, and margin); verify column mapping against your company's current Procore import template before uploading.

### Validation Rules & Implementation Notes

| Field / Area | Validation Rule | Expected Error Behavior |
|---|---|---|
| Cost Code | Must be unique; every assembly component must reference an existing Cost Code. | Flag duplicates or display `Unknown Code`. |
| Cost Description & Unit | Must be populated with valid measurement units. | Flag incomplete master records. |
| Resource Rates & Usage Factors | Numeric and non-negative. | Reject or flag invalid values. |
| Tender Item No, Qty & Unit | Must be populated; quantities numeric and non-negative. | Flag missing fields; guard against division by zero on Unit Sell Rate. |
| Assigned Assembly | Every priced BOQ row must map to a valid Assembly ID. | Display `Waiting for Mapping...` for unmapped rows. |
| Overhead / Risk / Margin Rates | Valid non-negative percentages. | Flag invalid pricing parameters. |
| WBS / Procore Cost Code & Category | Must align with target company WBS and accepted category codes. | Validate and reconcile total exported budget against mapped direct costs. |

**Environment & Integrity Notes:** Requires **Microsoft 365, Excel 2021, Excel 2024, or modern WPS** supporting dynamic arrays (`LET`, `MAP`, `LAMBDA`, `REDUCE`, `VSTACK`, `HSTACK`, `FILTER`, `XLOOKUP`). Keep dynamic spill areas unobstructed and avoid blank rows inside contiguous `COUNTA`-indexed input columns. Default blueprint ranges cover up to row 10,000.
